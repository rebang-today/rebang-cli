# rebang CLI 需求与决策记录

> 状态：草案，待评审。本文档位于开源仓库，不包含服务器地址、内部域名和后台接口。服务端实现细节见服务端仓库的 CLI 认证文档，两边只通过本文的决策编号（D-xx）互相引用。

## 1. 目标

`rebang` 是今日热榜（rebang.today）的官方命令行客户端，同时服务两类使用者：

- **人**：在终端里用键盘和鼠标浏览热榜，体验接近网站。
- **AI Agent 与脚本**：通过子命令拿到结构化结果，配合随版本发布的 Agent Skill 完成查询与研究任务。

用户登录后享有与网站一致的账号与会员能力。

## 2. 非目标（第一版不做）

- CLI 内购买、激活或续费会员（跳转网页完成）。
- 设置编辑、反馈、表情回应、推荐返利。
- 监控计划的创建、编辑、暂停、删除和通知设置（只做查看命中内容，见 D-27）。
- 客户端埋点遥测。
- macOS 代码签名与公证。
- 英文、日文界面（结构上预留）。
- 专门的接口契约文档（需要时直接阅读服务端代码）。

## 3. 决策

### 形态与技术

- **D-01 单一程序两种用法**：`rebang` 无参数进入全屏交互界面（TUI）；`rebang <子命令>` 为非交互调用。
- **D-02 技术栈**：Go + Bubble Tea（Lip Gloss、Bubbles）。模块路径 `github.com/rebang-today/rebang-cli`，命令名 `rebang`。
- **D-03 独立开源仓库**：`rebang-today/rebang-cli`，许可证 Apache-2.0。客户端不包含任何服务端代码，请求与响应结构在本仓库自行定义。
- **D-04 支持平台**：macOS、Linux、Windows，各自 amd64 与 arm64。
- **D-05 界面语言**：第一版仅中文；命令名、参数名、JSON 字段、错误码一律英文，保证 Agent 调用稳定。

### 账号与会员

- **D-10 登录方式**：浏览器设备授权（RFC 8628）。CLI 展示授权码并打开浏览器，用户在网站登录并确认后，CLI 获得专属 Token。网站已有的全部登录方式（邮箱验证码、密码 + 2FA、第三方登录）自动可用。支持 `--no-browser`，适配 SSH 等无桌面环境。
- **D-11 环境变量**：`REBANG_TOKEN` 优先级最高，供 CI 与 Agent 注入凭证。
- **D-12 凭证存储**：统一存放在文件中，不接入系统钥匙串。
  - macOS/Linux：`~/.config/rebang/auth.json`
  - Windows：`%AppData%\rebang\auth.json`
  - 文件权限 0600，原子写入（临时文件 + 重命名），文件格式带版本号。
- **D-13 Token 有效期**：90 天滑动续期，期间使用即自动顺延。CLI Token 独立于网页登录的会话上限，单个用户最多 10 台设备，可在网站设置中按设备吊销。
- **D-14 会员**：CLI 识别会员身份并享有与网站一致的会员能力（例如搜索时间窗口），所有会员判断由服务端完成，客户端不做额外限制。`rebang account` 展示会员状态与到期时间；购买与续费引导到网页。

### 交互界面（TUI）

- **D-20 第一版功能**：分类 → 榜单 → 子榜单浏览、回车用浏览器打开、复制链接、搜索、订阅、切换节点、手动与定时刷新。
- **D-21 布局**：顶部分类（菜单）栏，最前面是“订阅”（数字键 0，与网站 navigation.followingLabel 一致），启动时回到上次的位置（见 D-22），没有记忆时停在第一个服务端菜单；“订阅”的数据为用户订阅的 Tab（`/v1/tabs/following`，需登录，按返回顺序显示），未登录时左栏为空并提示 `rebang auth login`，没有订阅时提示去网站添加，接口报错时 r 重试；订阅里的“内容监控”（tab key `monitoring`）显示命中列表（见 D-27），左栏名称后显示总未读数。左栏为当前分类的来源平铺列表（没有 Tab 的分类列出节点），不做展开收起；右栏为标题行、子榜单条与榜单，下方为预览（见 D-26），子榜单条与网站一致在二级 Tab 多于 1 个时才显示（只有 1 个时 `tab` 无动作，请求仍带上它的 key）；底部状态栏显示登录与会员状态和快捷键提示。分类栏与子榜单条放不下时以当前项为中心截断，两端显示 ‹ ›；宽度不足 56 列时自动切换为单栏（左栏最宽 18 列 + 右栏至少 37 列）：单栏默认显示榜单（标题行为当前来源名，子榜单条照常显示），`←` 打开占满整栏的来源列表，`↑↓` 与左栏相同、实时切换来源（防抖），`→` 或回车回到榜单；单栏时有标题会因热度列被截断就隐藏热度列，优先显示标题；底部提示见 D-22。窗口小于 40 列 × 10 行时整屏只显示一行“窗口太小，至少需要 40×10”（宽度不够时截断），按键照常处理，`q` 能退出，放大后恢复原界面。鼠标悬停在分类、来源、子榜单与条目等可点击元素上时，通过 OSC 22 把指针切换为小手（kitty、Ghostty、foot 等支持，其他终端忽略），移开或退出时恢复终端默认指针；只在标准输出是终端时发送。公众号（tab key `wechat`）的默认子榜单与网站一致：未登录直接选“热门”；已登录先选“关注”，结果为空时自动切到“热门”并记住；用户手动选的子榜单不受影响。
- **D-22 键盘**：按键分栏，方向跟着界面走：竖排用 `↑↓`，栏与栏之间用 `←→`。焦点从不自动跳转，启动时在左栏。`↑↓`/`jk`、`PgUp`/`PgDn`（`ctrl+b`/`ctrl+f`）、`g`/`G`（`Home`/`End`）在当前栏内移动（左栏选来源，榜单选条目）；左栏移动时右栏实时跟着切换（先清空并显示新来源名），停下约 150ms 后才加载，到首尾停住不循环。`←`/`h` 去左栏（单栏时打开整栏的来源列表），已在左栏时不做任何事；`→`/`l` 回到榜单，左栏回车同样，防抖未触发时立即加载，已在榜单时不做任何事。`tab`/`shift+tab` 在两栏都循环切换子榜单并立即加载，到头后回到另一端，只有一个子榜单时不做任何事。`0`～`9` 与 `[` `]` 切换分类，每个分类记住上次的来源，每个来源记住上次手动选的子榜单。榜单中回车用浏览器打开；`Esc` 只用来退出搜索框、帮助与搜索结果，榜单中按 `Esc` 不切到左栏。空格向下翻预览，`p` 开关预览（见 D-26）；`/` 搜索，`y` 复制链接，`r` 刷新，`u` 在内容监控中切换全部、只看未读（见 D-27），`?` 帮助，`q` 退出。鼠标操作不变：点击来源焦点移到左栏，点击条目焦点移到榜单（单栏来源列表中点击即切换并回到榜单）。
  - 当前栏：焦点栏的选中行用强调色文字加选中底色、行首蓝色竖条，榜单焦点时标题行用强调色；非焦点栏的选中行只保留灰色竖条与加粗，不用强调色与底色。
  - 底部提示：左栏为“↑↓ 选来源  → 进入榜单  tab 子榜  0-9 分类  / 搜索  ? 帮助  q 退出”；榜单为“↑↓ 移动  ← 来源  tab 子榜  ↵ 打开  空格 翻预览  0-9 分类  / 搜索  ? 帮助  q 退出”（分类键按实际菜单数显示，如 0-8）；单栏整栏预览为“↑↓ 换条  空格 翻页  p/esc 返回  ? 帮助  q 退出”。内容监控中在“↵ 打开”后加“u 只看未读”，搜索结果中加“esc 返回榜单”；只有一个子榜单时不显示“tab 子榜”；预览关闭、看不到或内容放得下时不显示“空格 翻预览”（整栏预览的“空格 翻页”同样）。
  - 放不下时先逐级缩短左边的账号状态：去掉到期时间（“● 邮箱 · 会员”），再截短邮箱，最后只留“● 会员”（非会员为“● 非会员”，没有账号信息为“● 已登录”；登录失效缩成“● 登录已失效”）；整栏预览不显示账号状态。还放不下时按重要性去掉提示（同等重要时先去掉靠后的）：先去掉“↵ 打开”“0-9 分类”“/ 搜索”（整栏预览的“↑↓ 换条”同级），其次是“↑↓ 移动/选来源”“tab 子榜”“空格 翻预览”“u 只看未读”“esc 返回榜单”，“← 来源”“→ 进入榜单”“p/esc 返回”最后才去掉，“? 帮助”“q 退出”始终保留。
  - 列表为空时提示“暂无内容”与换榜单的按键：左栏焦点为“↓ 换一个榜单”，榜单焦点（包括单栏）为“← 换一个榜单”。
  - 位置记忆（当前菜单、各菜单的来源 key、各来源的子榜单 key，带 `version` 字段）按 key 而非下标保存在配置目录的 `tui-state.json`（与版本检查的 `state.json` 同目录，`REBANG_CONFIG_DIR` 可隔离），切换后约 1 秒防抖写入、退出时再写一次，原子写入，文件 0600、目录 0700；读写失败静默忽略，文件损坏或版本不认识时当作没有记忆。启动时回到上次的菜单、来源与子榜单，key 已不存在时逐级回退到该菜单的第一个来源与第一个子榜单，菜单不存在时回到第一个服务端菜单；上次停在“订阅”而现在未登录时照常停在订阅并提示登录。不保存列表光标、滚动位置与搜索词。公众号默认子榜单规则只在没有记忆时生效。
- **D-23 鼠标**：点击分类、左栏来源、子榜单即切换并加载（点左栏时焦点在左栏，其余不改变焦点）；列表单击选中、双击打开；悬停高亮（滚动后对应指针下实际的行）。滚轮指针在哪个区域就滚哪个区域，不改变选中项：
  - 榜单与左栏：每格 3 行，只滚视窗，选中项可以滚出视野；之后按 `↑↓` 从选中项继续移动并把视窗拉回选中项。预览始终跟着选中项。
  - 预览区（榜单下方，含分隔线；单栏整栏预览的正文）：每格 3 行，到顶或到底停住、不回绕；空格翻页不变。点击预览区不选中条目。
  - 顶部菜单栏与子榜单条：竖向或横向滚轮都按项横向平移这一行的可视窗口，不切换分类或子榜单，‹ › 按新窗口显示，点击命中跟着平移后的位置，点击后保持窗口；用键盘切换分类或子榜单（或换来源）后窗口重新以选中项为中心。
  - 帮助与搜索框打开时滚轮不做任何事。
- **D-24 主题**：自动跟随终端深色或浅色。配色与网站一致：强调色、品牌标识、选中与当前分类的底色浅色模式用网站的蓝色（`--primary` #2C5CF5，背景为同色调的浅蓝）；深色模式下网站蓝发闷，改用 #7AA2F7，选中行 #283457、当前分类与提示 #1F2A44、品牌标识 #3D63D8（方案 B）；只有前 3 名序号用网站的橙色（`--rank-top` #F7670D，浅色背景下略加深以保证对比度）。命令行 table 与卡片的强调色同为蓝色，前 3 名序号为橙色。
- **D-25 显示文本清洗**：标题、描述、来源名、子榜单名、搜索结果等外部文本在交互界面和 table 输出中去掉 Unicode 格式字符（Cf，如零宽字符、双向文本控制符、U+FEFF、软连字符）与控制字符（Cc），换行与制表符替换为空格并折叠连续空白，避免终端宽度计算不一致导致错行；`-o json` 保留接口原文。
- **D-26 AI 总结**：条目的 AI 总结来自 `POST /v1/item/insights/batch`（`{"item_keys": [...]}`，单次 1～50 个，只返回有总结的 item_key 与 `summary_short`）与 `GET /v1/item/insight?item_key=`（`summary_short` 与 `detail`，没有总结时 404 + 业务码 1003），两者都是可选登录：未登录也可调用，已登录时照常带上令牌。
  - 批量查询：每页列表或搜索结果加载后（登录与否都查询）批量查询本页 item_key（超过 50 个分批），结果按 item_key 缓存在内存，查过的不再重复请求；失败静默；返回 401（令牌失效）时按 D-34 标记登录失效，之后不再请求。列表不再显示 `✦` 标记，批量结果只用来决定预览是否有总结、是否需要请求完整总结。
  - 预览内容：元信息一行“来源 · 时间 · 热度”（内容监控为“来源 · 命中时间”，下一行“命中：计划名：命中词”，多个计划用“；”分隔）；有总结时为小标题“AI 总结”、一句话总结，再是各分区（与原详情页的渲染一致）；有描述时为小标题“简介”与描述（没有描述，或去掉“[图片]”这类方括号占位文字与空白后为空时，省略整段）；两者都没有时显示“暂无摘要”。小标题统一使用“AI 总结”的样式。单栏整栏预览在元信息前加一行标题。
  - 完整总结：只对批量结果中有总结的条目请求 `GET /v1/item/insight`，光标停下约 200ms 后才请求，快速移动只请求最后停下的条目；结果按 item_key 缓存（失败也缓存，不反复请求）。加载中显示一句话总结，分区位置显示“加载中…”；失败（含 404）只显示一句话总结，不显示错误；401 按 D-34 标记登录失效；未登录照常请求。看不到预览时不请求。
  - 翻页：内容超出预览区时最后一行专门显示右对齐的“↓ 更多”，不覆盖正文；空格向下翻一屏，到底后再按回到开头；内容放得下时空格不做任何事；换条目后回到顶部。
  - 布局：双栏（至少 56 列）时预览一律在榜单下方（上方一条分隔线），约占右栏高度的 40%（至少 6 行），不足 24 行时不显示；单栏默认不显示，`p` 切换整栏预览（`↑↓` 仍移动榜单光标、预览跟着刷新，空格翻页，`p` 或 `Esc` 回到榜单，`←` 打开来源列表）。宽屏时 `p` 打开或关闭预览，开关保存在 `tui-state.json` 的 `preview` 字段（缺省为打开）；列表为空时不显示。
  - 原全屏详情页已删除，空格只用来翻预览；列表翻页使用 `PgUp`/`PgDn`（`ctrl+b`/`ctrl+f`）。
  - 分区顺序固定为要点（`points`）→ 经过（`timeline`，`time` 可为空）→ 观点（`viewpoints`：概括、论据、原话、署名，`by`/`quote` 可为空）→ 网友怎么看（`reactions`：`mood` 与 `voices`），缺失的分区跳过，`quotes` 等不认识的分区忽略，`keywords`、`debug` 不读取也不显示。文本中的一处 `**…**` 渲染为加粗，其他 Markdown 原样显示；原话加中文引号并以灰色显示。所有文本经 D-25 清洗后按显示宽度折行；折行做简单的禁则处理：“，。、；：！？”和右引号、右括号等不放在行首，连同上一行最后一个字一起移到下一行。
  - 命令行：`rebang summary <item_key>`（item_key 来自 `list`/`search` 的 JSON），默认输出可读文本，`-o json` 输出 `{summary_short, detail}`（detail 为服务端原样返回的 JSON，不含 `keywords`、`debug`），`-o md` 输出 Markdown。不要求登录（令牌失效时服务端 401，退出码 3）；没有总结退出码 8（`summary_not_found`）；只有 HTTP 404 而没有业务码（如服务端没有该接口）不算“没有总结”，按一般错误处理。

- **D-27 内容监控（只读）**：只查看命中内容，创建、编辑、暂停、删除计划与通知设置在网站完成。接口均需登录（信封格式）：`GET /v1/monitoring/plans`（`id`、`name`、`keywords`、`status`：`active`/`paused`/`membership_expired`）、`GET /v1/monitoring/unread-counts`（`{all, plans:[{plan_id, unread_count}]}`）、`GET /v1/monitoring/hits?page_size=30&plan_id=&cursor=&read_status=all|unread`（cursor 翻页，单页最多 30）、`POST /v1/monitoring/read`（`{"item_key"}`，返回最新未读数）。
  - 交互界面：订阅 → 内容监控显示命中列表。子榜单条为“全部 N”加各计划与其未读数，已暂停、会员过期的计划后面用灰色标注“已暂停”“会员过期”；计划选择不保存。每行：未读圆点（强调色，已读留空不改变对齐）、标题、灰色“来源 · 命中词”，右侧为相对命中时间（刚刚、N 分钟前、N 小时前、昨天 HH:MM、M月D日 HH:MM，跨年显示年月日），不显示热度。先加载 30 条，光标进入最后 5 条时自动加载下一页，没有更多后停止；下一页失败时提示错误并停止自动加载。`r` 与定时刷新从第一页重新加载。回车用浏览器打开原文，同时在后台标记已读（不阻塞，失败不影响打开），本地立即去掉圆点并用返回的未读数更新子榜单条与左栏；只看预览不标记已读。`u` 切换全部/只看未读，标题行显示“内容监控 · 只看未读”，开关保存在 `tui-state.json` 的 `monitor_unread`。预览在元信息下显示“命中”行（见 D-26），AI 总结照常显示。没有计划时提示“还没有监控计划，可在网站创建：<网站>/monitoring”；未登录沿用订阅的登录提示，不请求监控接口；401 按 D-34 处理。底部提示含“u 只看未读”（只看未读时为“u 看全部”）。
  - 命令行：`rebang monitor plans`（计划、关键词、状态与未读数）与 `rebang monitor hits [--plan <ID>] [--unread] [-n 30]`（`-n` 取 1～100，按 cursor 翻页凑够条数），都需登录，支持 table/md/json，只读、不标记已读。hits 的 JSON 字段：`item_key`、`title`、`description`、`source`、`source_name`、`url`、`mobile_url`、`matched_at`、`published_at`、`is_read`、`matches[]`（`plan_id`、`plan_name`、`matched_keywords`），外层 `plan_id`、`unread_only`、`has_more`、`items`。

- **D-31 输出格式**：查询类命令支持 `-o json|md|table`。输出到终端时默认 `table`，被管道或 Agent 调用时默认 `json`。`table` 是给人看的格式，可使用卡片、颜色等样式，不作为稳定接口；只在输出连接到终端且未设置 `NO_COLOR` 时上色。`json` 与 `md` 是给 Agent 的格式，变更需遵守 D-56。
- **D-32 错误与退出码**：错误统一输出结构化 JSON（`code`、`message`、`hint`）。退出码固定：0 成功、1 一般错误、2 参数错误、3 未登录或凭证失效、4 需要会员、5 被限流、6 网络错误、7 需要升级、8 条目暂无 AI 总结（`rebang summary`，见 D-26）。
- **D-33 请求标识**：每个请求携带 `User-Agent: rebang-cli/<版本> (<系统>/<架构>)`，非交互调用另带调用方式标记，供服务端区分人与 Agent 流量。UA 中不得包含 `go-http-client` 等通用库标识。
- **D-34 网络错误不清凭证**：只有服务端明确判定 Token 无效、过期或已吊销时，才提示重新登录；网络错误、超时、5xx 一律不清除本地凭证。

### 升级与发布

- **D-50 升级策略**：
  - `rebang update` 手动升级。
  - 交互使用时每天最多检查一次新版本并提示。
  - JSON 输出（非终端或 `-o json`）共用同一个每天一次的检查缓存（`state.json`），缓存过期时联网检查一次，最多等 1.5 秒，失败静默；结果只通过 JSON 的 `_notice` 字段告知（见 D-63），不向标准错误输出提示。md、table 的非交互调用不检查。
  - 默认不静默替换程序，可通过 `auto_update` 开启。
  - 版本低于 `min_version` 时拒绝执行并提示升级（退出码 7）。
- **D-51 版本信息文件**：自有 CDN 上的静态文件 `cli/manifest.json`，包含最新版本、`min_version`、各平台下载地址与 sha256。升级只读取这个文件；需要强制升级时手动修改 `min_version`。
- **D-52 完整性校验**：下载后校验 sha256，并用 minisign 验证签名，公钥内置在程序中。
- **D-53 分发渠道**：自有 CDN 为主（国内下载快），GitHub Releases 与 Homebrew tap（`rebang-today/homebrew-tap`）为辅。
- **D-54 安装方式**：
  - macOS/Linux：`curl -fsSL <官网>/cli/install.sh | sh`
  - Windows：`irm <官网>/cli/install.ps1 | iex`
  - macOS 另可 `brew install rebang-today/tap/rebang`
  - 不提供 npm 与 scoop。
  - 安装脚本按需询问是否同时安装 Agent Skill，最后只提示登录是可选的（见 D-65）。
- **D-55 发版流水线**：推送 `v*` tag 触发 GitHub Actions，由 goreleaser 依次完成：构建、生成 sha256 与 minisign 签名、发布 GitHub Releases、更新 Homebrew tap、上传 CDN，**最后**写入 `manifest.json`。需要的 Secrets：仅限 `cli/` 目录写权限的 OSS 子账号密钥、minisign 私钥、tap 仓库写权限 token。
- **D-56 版本号**：语义化版本，从 v0.1.0 开始。1.0 之前允许不兼容变更；1.0 之后命令名、参数、JSON 字段、退出码均视为稳定接口，不兼容变更必须升主版本。每个版本附带更新日志。

### Agent Skill

- **D-60 内嵌并随版本发布**：skill 文件编译进程序，`rebang skill install` 写入各 Agent 的 skill 目录（如 `~/.claude/skills/rebang`）。`rebang update` 升级后自动同步已安装的 skill，保证 skill 与程序版本一致。skill 中注明适用的版本范围。
- **D-61 结构**：一个名为 `rebang` 的 skill。`SKILL.md` 为命令用法，`references/research.md` 为研究流程。
- **D-62 研究流程**：
  1. 识别主体和同义词，拆成多条子查询。
  2. 多次调用 `rebang search` 检索。
  3. 按链接去重，检查结果是否真的在讲用户问的主体，再按热度排序。
  4. 综合作答，每条结论附原链接；证据不足时如实说明。
  5. 遇到退出码 4（需要会员，例如普通用户只能搜当天），如实告知用户，不得编造结果。
- **D-63 JSON 版本提醒**：JSON 输出时，若每天一次的检查发现新版本，或本机已安装的 skill（`~/.claude`、`~/.codex`、`~/.agents` 下由 rebang 安装的）与程序版本不一致，在结果的顶层对象末尾附加 `_notice`：`{"update":{"current","latest","command":"rebang update"},"skill":{"installed","expected","dirs","command":"rebang skill install"}}`，没有的部分省略，都没有时不出现该字段。结果不是对象时不附加；`rebang update` 自身不附加；开发版不检查；`REBANG_NO_NOTICE=1` 关闭。skill 要求 Agent 先完成任务，最后提醒用户运行对应命令，不得自行升级或重装。
- **D-64 按需登录**：热榜、搜索、AI 总结不需要登录，安装与 Agent 指引中都不把登录作为必要步骤。skill 规定：只有命令以退出码 3 结束时，Agent 才告诉用户该功能需要登录并询问是否现在登录；用户同意后在后台运行 `rebang auth login --no-browser`，把链接与授权码原样转告用户，等命令自行退出后运行 `rebang auth status` 确认，再重试原命令；用户拒绝时继续用无需登录的功能完成任务。为此 `auth login` 在 JSON 输出时拿到授权码后立即（第一次轮询之前）在标准错误输出可读提示与一行 JSON：`{"event":"login_pending","verification_uri","verification_uri_complete","user_code","expires_in"}`；终端 table 模式不输出这一行。
- **D-65 安装时安装 skill**：`install.sh` / `install.ps1` 安装完成后，检测到 `~/.claude`、`~/.codex`、`~/.agents` 任一存在时询问“检测到 Claude Code、Codex，是否安装 rebang Agent Skill？[Y/n]”（列出检测到的 Agent），默认是，确认后运行新装程序的 `rebang skill install`，失败不影响程序安装。`curl | sh` 时从 `/dev/tty` 读取回答；没有终端（CI 等，Windows 为输入被重定向）时不安装。`REBANG_INSTALL_SKILL=1|0` 或参数 `--with-skill` / `--no-skill` 明确选择，不再询问；未检测到 Agent 时不询问，只提示可运行 `rebang skill install`。结尾的登录提示为可选：“可选：rebang auth login 登录后可用我的关注、内容监控等功能”，不追问、不打开浏览器。README 提供交给 Agent 的安装指引：安装脚本 → `rebang skill install` → 用一条无需登录的命令（如 `rebang list`）验证，不包含登录步骤。

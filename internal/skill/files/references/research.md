# 热榜研究流程

适用版本：rebang {{VERSION}}。

当用户想了解「某个话题 / 人物 / 公司 / 事件最近在热榜上的情况」时，按以下步骤进行。

## 1. 识别主体，拆分子查询

- 明确用户问的主体是什么，以及时间范围（今天？最近一周？）。
- 列出主体的同义词、简称、英文名、相关人物或产品名。例如「英伟达」→ 英伟达、NVIDIA、黄仁勋、H20。
- 每个子查询保持简短（1~3 个词），搜索按关键词匹配，长句效果差。

## 2. 多次调用 rebang search

```bash
rebang search "英伟达" --days 7 -n 50 -o json
rebang search "NVIDIA" --days 7 -n 50 -o json
rebang search "黄仁勋" --days 7 -n 50 -o json
```

- 只问今天时不加 `--days`。
- 需要看某个平台时加 `--source <TAB_KEY>`（会员功能）。
- 想了解当下全局热度时，可以再用 `rebang list --tab <TAB_KEY>` 查看对应平台的实时榜单。

## 3. 去重、核对、排序

- 按 `url` 去重；同一事件在不同平台的条目保留，用于说明跨平台热度。
- 逐条检查标题与 `snippet` 是否真的在讲用户问的主体，剔除同名、仅顺带提及等无关结果。
- 排序依据：出现的平台数量、在榜时间（`first_seen_at` 到 `last_seen_at`）、在实时榜单中的名次与 `heat`。

## 4. 综合作答

- 先给结论（例如「最近 7 天主要有三件事上了热榜」），再分条展开。
- 每条结论附原链接，注明来源平台与时间。
- 证据不足时如实说明，例如「只在 1 个平台出现过 1 次」。不要用常识或猜测补全热榜上不存在的内容。

## 5. 处理会员限制

- 退出码 4（`membership_required`）表示该查询需要会员，例如普通用户只能搜索当天。
- 如实告诉用户：「搜索更早的时间需要今日热榜会员」，并改为在权限内完成（例如只查当天），说明结果因此受限。
- 不得编造被限制部分的结果。用户想开通时，引导访问 `rebang account` 输出中的 `manage_url`。

## 6. 其他错误

- 退出码 3：请用户运行 `rebang auth login` 后再试。
- 退出码 5：被限流，减少子查询数量，稍后再试。
- 退出码 6：网络或服务端错误，可重试一次，仍失败则告知用户。
